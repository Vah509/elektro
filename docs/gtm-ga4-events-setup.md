## Конфигурация (Google Tag)

В контейнере уже существовал тег типа **"Тег Google"** (новый формат GTM,
заменяет старый "GA4 Configuration") с идентификатором `G-BQR848YQKK`.
В интерфейсе тегов он отображается как:

```
GA4 - Config   |   Тип: Ter Google   |   Триггер: Initialization - All Pages
```

("Ter Google" — это отображаемое название типа тега в русской локализации
GTM для нового формата Google Tag; технически это тот же механизм, что и
"Google Аналитика: событие GA4" использует под капотом).

**Важно:** при создании нового тега типа "Google Аналитика: событие GA4"
GTM **автоматически** находит этот Google Tag и привязывает к нему событие —
отдельно выбирать "Configuration Tag" из списка не нужно, в отличие от
старого интерфейса GTM. Поле называется "Идентификатор потока данных",
и туда либо вписывается `G-BQR848YQKK` вручную, либо выбирается переменная
`GA4 - Measurement ID` (константа, уже существует в разделе Переменные —
предпочтительный способ, чтобы не дублировать ID в каждом теге).

### Click — WhatsApp
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click URL}}` содержит `wa.me/380981527555`

### Click — Email
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click URL}}` содержит `cdn-cgi/l/email-protection`

### Click — Email (mailto)
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click URL}}` содержит `mailto:elektroschit.info@gmail.com`

⚠️ **Email-ссылка ведёт себя непоследовательно на сайте.** На одних
страницах/загрузках Cloudflare (Scrape Shield / email obfuscation)
переписывает `mailto:` на `/cdn-cgi/l/email-protection#...` и раскодирует
его в браузере уже после рендера; на других страницах в момент клика
`Click URL` фактически равен чистому `mailto:elektroschit.info@gmail.com`
(подтверждено логами Tag Assistant 2026-09-06 на разных страницах сайта).
Причина такого расхождения не выяснена (возможно, кэш Cloudflare отдаёт
разные версии HTML в разное время). Из-за этого **оба** триггера обязательны
и оба привязаны к одному тегу `GA4 — click_email` — тег сработает, какой бы
вариант URL ни оказался у конкретного посетителя.

### Click — Map
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click URL}}` содержит `google.com/maps`

### Page View — Portfolio Item
- Тип: Просмотр страницы → Некоторые просмотры страниц
- Условие: `{{Page Path}}` соответствует регулярному `^/vykonani-roboty/[^/]+/?$`
(отсекает страницу-каталог `/vykonani-roboty/`, срабатывает только на карточках)

### Click — FAQ
- Тип: Клик - Все элементы → Некоторые клики
- Условие: `{{Click Element}}` соответствует селектору CSS
  `.em-faq-question, .em-faq-question *`

⚠️ **Расширенный селектор обязателен.** Кнопка FAQ содержит вложенную
SVG-иконку "+" (`.em-faq-icon`). Изначальный селектор `.em-faq-question`
(без `*`) не засчитывал клики именно по иконке — только по остальной части
кнопки. Исправлено и подтверждено в Preview 2026-09-06.

### Click — Also Make
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click Element}}` соответствует селектору CSS
  `.em-product-card, .em-product-card *`

(Аналогично расширено на дочерние элементы — заголовок/текст внутри карточки.)

### Click — Gallery Photo
- Тип: Клик - Все элементы → Некоторые клики
- Условие: `{{Click Element}}` соответствует селектору CSS
  `.em-gallery-item, .em-gallery-item *`

(Аналогично расширено — клик по самому `<img>` внутри карточки тоже засчитывается.)

### Click — CTA Header
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click Classes}}` содержит `em-header-cta`
- Кнопка "Залишити заявку" в шапке сайта — присутствует на **каждой** странице.
  Класс `.em-header-cta` уникален для этой кнопки.

### Click — CTA Hero
- Тип: Клик - Только ссылки → Некоторые клики по ссылкам
- Условие: `{{Click Classes}}` содержит `em-btn-primary`

⚠️ **Класс `.em-btn-primary` используется на двух разных кнопках** на
продуктовых страницах: кнопке "Замовити / Зв'язатися з нами" в hero-блоке
**и** кнопке "Переглянути роботи →" в блоке галереи. Событие `click_cta_hero`
считает клики по обеим вместе — это принятое упрощение (см. раздел "Известные
компромиссы" ниже). Различие "главная / конкретная продуктовая страница"
видно из параметра `page_path` в самом событии GA4.

## Известные компромиссы (сознательно принятые упрощения)

- **`open_faq`** не различает открытие/закрытие аккордеона — фиксируется
  каждый клик по кнопке вопроса. Для аналитики интереса к конкретным
  вопросам этого достаточно; для точного UX-анализа потребовалась бы
  правка JS-кода сайта.
- **`click_email`** не различает, по какой из двух email-ссылок на странице
  кликнули (в блоке ContactBlock или в футере) — общий факт клика по email.
- **`click_cta_hero`** объединяет клики по кнопке "Замовити / Зв'язатися
  з нами" (hero) и кнопке "Переглянути роботи →" (блок галереи) — обе
  используют класс `.em-btn-primary`. Различить их отдельным событием
  можно в будущем, если понадобится — потребуется либо новый уникальный
  класс на одной из кнопок в коде сайта, либо селектор по href.
- **Hero-коллаж** (4 фото в верхнем блоке продуктовой страницы) тоже
  открывает Lightbox через collage-обвязку, но использует другой JS-путь,
  не входит в `Click — Gallery Photo`. Если понадобится считать и его —
  нужен отдельный триггер по классу коллажа.

## Что дальше

1. Подождать 1–3 дня, чтобы накопились данные в GA4
2. В GA4 (Admin → Events) отметить как конверсии: `click_phone`,
   `click_viber`, `click_telegram`, `click_whatsapp`, `click_email`,
   `click_map` — переключатель "Mark as conversion"
3. Решить, нужно ли также отмечать конверсией `click_cta_header` /
   `click_cta_hero` — это кнопки-якори к блоку контактов, не сами по себе
   контактные действия, но могут быть полезны как микро-конверсия для
   отслеживания намерения
4. Создать аккаунт Google Ads
5. Связать GA4 ↔ Google Ads ("Paid & Organic" отчёт)
6. Импортировать конверсии из GA4 в Google Ads для настройки автостратегий
   ставок на реальные заявки, а не просто клики по рекламе
