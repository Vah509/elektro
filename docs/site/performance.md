## 3. Что не помогло или оказалось пустым

- **Частые повторные замеры.** Три итоговых замера в разное время суток дали одну и ту же среднюю (96,8 / 96,9 / 96,8): зависимости от времени суток нет, дальше такие серии бессмысленны.
- **Строки «Регрессии» в Telegram.** Почти все — шум (одна и та же страница в разных прогонах даёт от 71 до 99). Решения по ним не принимаем.
- **Предупреждение аудита `work-similar-few`** (40 шт. в пятницу) — ложное срабатывание проверки, блок «Схожі роботи» работает. В субботу предупреждений уже нет.
- **Разбивка этапов LCP в отчёте.** На карточках работ сумма этапов ≈ 0,2 с при LCP 2–4 с, то есть этапы с общим LCP не сходятся. Совет «LCP-картинка не оптимизирована для раннего обнаружения» (`/vykonani-roboty/`) без проверки в коде считать надёжным нельзя.
- **TBT как повод для паники.** Он зелёный, а в «Топе причин» его главный источник — GTM/GA4 (см. раздел 5), то есть цена аналитики, а не дефект страниц.

## 4. Как читать результаты

- Решения принимаем по **медиане нескольких прогонов** и по причинам, которые **повторяются** в разных отчётах.
- Разброс между прогонами > 10 пунктов был у 15–17 из 68 страниц в каждом итоговом замере. Это обычный шум PSI.
- Lab (локальный Lighthouse) сравниваем только с lab, PSI — только с PSI.
- Пороги: LCP ≤ 2,5 с, TBT ≤ 200 мс, CLS ≤ 0,1.

## 5. Что можно сделать позже (не срочно)

Порядок — по пользе.

1. **CLS на `/ru/uslugi-i-produktsiya/krm/`.** 0,185–0,191 во всех трёх итоговых замерах (у украинской версии `krm` — 0,001). Единственный воспроизводимый дефект. Сдвигающийся элемент в отчёте не назван — нужен `lab`-прогон с трейсом.
2. **Разовые сдвиги CLS.** `/posluhy-ta-produktsiia/shuz/` — 0,266 в 2 из 9 замеров (в остальных 0,023), `dvyhuny` — 0,126 один раз, `/ru/…/shchity-upravleniya-dvigatelyami/` — 0,115 один раз. Из-за них оценка этих страниц иногда падает до 79–86. Причина не установлена.
3. **Исключить Lighthouse из аналитики.** За 30–31.10 выполнено ≈ 1100 загрузок страниц тестами; в GTM исключение user-agent `Chrome-Lighthouse` пока не сделано, поэтому они могли попасть в GA4/Clarity.
4. **`public/_headers`:** кэш `/_astro/*` на год (`immutable`) вместо 4 часов. Выигрыш только для повторных визитов; это единственные 2 предупреждения 🟡 в аудите.
5. **Проверить первое фото карточек работ:** есть ли `fetchpriority="high"` и нет ли `loading="lazy"` у главного фото и у первых карточек каталога. В коде не проверялось.
6. **GTM/GA4** (Script Evaluation ≈ 270–450 мс, ≈ 306 КиБ третьих сторон, из них ≈ 140 КиБ неиспользуемого JS). Вариант — отложенная загрузка GTM, но тогда часть коротких визитов не попадёт в аналитику. Решать вместе с задачами по аналитике.
7. **Cloudflare:** в lab-отчёте виден скрипт `/cdn-cgi/challenge-platform/scripts/jsd/main.js` (≈ 300 мс главного потока), а `/cdn-cgi/…/email-decode.min.js` попадает в «блокирующие» на `/pro-nas/`. Оба вставляет Cloudflare; отключать их или нет — решать по пользе, а не по оценке.
8. **Информационное `script-no-defer` (242 шт.):** `em-site.js` и `email-decode.min.js` без `defer`. Оба стоят в конце страницы; по отчётам PSI заметного вреда нет.

## 6. Чего тесты не показывают

- **Реальных пользователей:** CrUX пуст, INP (отклик на действия) нигде не измеряется. Замеры идут из дата-центров, а не из Украины (TTFB в PSI 2–4 мс — это близость к краю Cloudflare, не показатель для пользователей).
- **Работу интерфейса:** лайтбокс, фильтры каталога, FAQ, кнопки связи — проверяется только структура HTML.
- **Повторные визиты:** кэш в тестах всегда холодный.
- **Десктоп:** в наборе всего 4 страницы (`/`, `/ru/`, `hrshch`, каталог).

## 7. Когда проверять снова

- Добавили карточки работ → режим `audit` (структура).
- Правили конкретные страницы → `targets`, 3 прогона; до слияния — через `base` на preview-адрес.
- Причина непонятна → `lab` на тех же страницах.
- Большие изменения (новые блоки, смена скриптов, шрифтов, фото) → `standard`, при необходимости `final`.
- Пересматривать вопрос производительности стоит, если на **повторных** замерах медианы страниц опускаются ниже 90 или меняется состав сторонних скриптов.
