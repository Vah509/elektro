## 1. Как доставлять изменения (ZIP → `ai-updates/`)

### Формат ZIP
- Без корневой папки: файлы лежат сразу в корне архива.
- Пути repo-relative: `src/pages/posluhy-ta-produktsiia/shuz.astro`, `src/assets/images/shuz/….jpg`, `docs/site/architecture.md`.
- **Размер архива ≤ 2 МБ.** Загрузка с телефона через GitHub UI падает на 4–6 МБ («Something went really wrong»). Много фото → несколько архивов (по одной папке/небольшими пачками).
- **Порядок:** фото-ZIP безопасны в любом порядке (пока на них нет ссылок). Код-ZIP, который ссылается на новые фото, — **последним**; если загрузить раньше фото, тестовая сборка упадёт («файл не знайдено»). Карточка портфолио: фото и `.md` в одном ZIP либо фото раньше `.md`.
- `delete.txt` внутри ZIP **больше не работает** (в `process-update.js` и `lib/staging.js` обработки нет — файл просто окажется лишним файлом в корне). Для удаления — п. 2.
- Файлы в `.github/workflows/` через ZIP не заливаются (у бота нет права менять workflow): добавляются вручную через GitHub UI.
- Загрузка в `main` = сразу боевой сайт (Cloudflare деплоит `main`). Для экспериментов — отдельная ветка (workflow срабатывает на любой ветке и пушит в `${{ github.ref_name }}`), проверка на preview-адресе ветки, слияние через Pull Request.

### Как загрузить
GitHub → репозиторий → папка `ai-updates/` → Add file → Upload files → ZIP → Commit. Через несколько минут приходят два сообщения в Telegram.

### Что происходит (workflow `unzip-and-update.yml`)
Триггер: push, изменивший `ai-updates/**.zip`. Шаги job:
1. checkout с полной историей (`fetch-depth: 0`);
2. проверка, что в `ai-updates/` сейчас есть ZIP (защита от зацикливания: сам коммит бота удаляет ZIP и тоже подпадает под триггер — тогда job завершается без действий);
3. Node 20, git-пользователь бота, `npm install`;
4. `node scripts/process-update.js` (секреты `TELEGRAM_TOKEN`, `TELEGRAM_TO`);
5. «Commit and Push changes» — `if: always()`: `git add .` → коммит `🤖 Авто-обновление сайта` → `git push origin <ветка>`. Выполняется ВСЕГДА, чтобы удаление ZIP попало в репозиторий даже при провале сборки. При успехе в коммит едут и файлы архива, и новый `lastmod-map.json`; при провале — только удаление ZIP.

### `process-update.js`, по шагам
1. Ищет первый `*.zip` в `ai-updates/`; нет — выход без действий. (Несколько ZIP в одном коммите обрабатываются по одному: после коммита бота удаление первого снова даёт триггер.)
2. Читает список файлов архива (`lib/read-archive.js`, `unzip -l`).
3. Считает карту дат (`lib/lastmod.js · computeLastmodMap`) по реальной git-истории ДО любых изменений: сканируются `src/pages` (рекурсивно, включая `ru/`) и `src/content/vykonani-roboty` (`.md`); файлы с именем на `[` пропускаются; нет истории — сегодняшняя дата (счётчик `gitFailures`).
4. `applyArchiveDatesOverride`: для КАЖДОГО `.astro` и `.md` из списка архива (кроме `[…]`) ставит сегодняшнюю дату. Побочный эффект: если в ZIP лежат `.astro`/`.md` вне страниц (компоненты, `docs/*.md`), их ключи тоже попадут в `lastmod-map.json`. На sitemap это не влияет (он берёт только ключи страниц), файл слегка «пухнет».
5. Создаёт staging `/tmp/em-staging` (`cp -a` репозитория без `.git`, вместе с `node_modules`) и распаковывает ZIP поверх (`unzip -o`). Реальный репозиторий пока не тронут.
6. Фото (`lib/optimize-photos.js`): для всех `.jpg/.jpeg` из архива, по расширению (путь не важен): ширина ≤ 1200 px → «ОК»; > 1200 → сжатие до 1200 px, JPEG q85, строка «ОПТ» (размер до → после); ошибка анализа → отдельная строка, остальные файлы продолжаются.
7. Telegram, сообщение 1: репозиторий, время (Europe/Bratislava), имя ZIP, список файлов (кроме фото), отчёт по фото или «Нових зображень в архіві немає».
8. Тестовая сборка `npm run build` в staging (`lib/test-build.js`).
9. Успех: пишет `lastmod-map.json` в staging, `promoteToRepo` копирует staging в репозиторий (`dist/` и `node_modules/` временно выносятся и не копируются). Провал: репозиторий НЕ меняется (ни файлы, ни даты).
10. Telegram, сообщение 2: 🟢 «Оновлення успішне (Astro Build розгорнуто)» либо 🔴 «Помилка збірки» + последние ~8 строк ошибки.
11. `finally`: ZIP удаляется ВСЕГДА (даже при неожиданном исключении), staging убирается.
12. Код выхода: 0 — успех; 1 — провал сборки или неожиданная ошибка.

Тестовая сборка защищает репозиторий от падения build, но не от визуальных ошибок: после деплоя проверять руками. Опечатка в пути фото роняет сборку в staging — это ожидаемая защита.

### Если пришло 🔴
Ничего не применено. Исправить причину (текст ошибки в сообщении 2) и загрузить исправленный ZIP заново.

## 2. Удаление файлов (`ai-deletes/`)

ПОСТОЯННЫЙ механизм вместо `delete.txt`. Состав: папка `ai-deletes/`, `scripts/process-deletes.js`, `.github/workflows/delete-files.yml` (триггер — push файла `ai-deletes/*.txt`; workflow правится только вручную через GitHub).

### Порядок (обязателен)
1. Составить список: **один путь на строку**, от корня репозитория, без `/` в начале, например `src/assets/images/vykonani-roboty/slug/file.jpg`. Пустые строки и строки на `#` игнорируются.
2. Сначала залить **пробный** файл: имя `dry-<что-угодно>.txt` (или первая строка `# dry-run`) в `ai-deletes/`. Скрипт ничего не удаляет, присылает 🟡 с числами «до видалення / вже немає / відхилено». Ожидаемо: `N / 0 / 0`.
3. Если цифры верны — залить тот же список под обычным именем (без `dry-`). Скрипт делает тестовую сборку в staging без этих файлов; при успехе удаляет файлы (и пустые родительские папки), коммитит и присылает 🟢 «Видалено файлів: N». Сам `.txt` удаляется всегда.
4. Если сборка в staging падает (на файл есть ссылка!) — не удаляется ничего, 🔴 с текстом ошибки.

### Правила безопасности (зашиты в скрипт)
- Разрешены только пути в `public/`, `src/`, `docs/`. Только файлы: папка в списке = отклонение.
- Запрещены: `..`, абсолютные пути, обратные слеши, кавычки, симлинки.
- Защищены от удаления: `src/config.ts`, `src/content/config.ts`, `src/data/tags-registry.ts`, `src/data/lastmod-map.json`, `public/robots.txt`, `public/js/em-site.js`.
- Лимит 300 файлов на список (больше — 🔴, ничего не удаляется; разбить на несколько `.txt`).
- Любой отклонённый путь отменяет ВЕСЬ список. «Файла вже немає» — не ошибка (считается отдельно).
- Коммитятся только `ai-deletes`, `public`, `src`, `docs` (workflow: `git add -A ai-deletes public src docs`, коммит `🤖 Видалення файлів зі списку`).
- Нельзя удалять этим способом: `.github/`, `scripts/`, `dist/`, `node_modules/`, файлы в корне.

История использования: удалено 122 файла (старые `public/images/<9 папок>` и `-sm.jpg`) и 213 оригиналов фото портфолио из `public/images/vykonani-roboty/` (список `portfolio-originals.txt`, пробный `dry-portfolio-originals.txt`).

## 3. Sitemap и `lastmod-map.json`

`src/pages/sitemap.xml.ts` — собственный эндпоинт (без `@astrojs/sitemap`). Git во время сборки на Cloudflare не используется: Cloudflare клонирует репозиторий неглубоко, `git log` там не работает. Даты считаются один раз в GitHub Actions (п. 1, шаги 3–4) и хранятся в `src/data/lastmod-map.json`: `{ "src/pages/kontakty.astro": "2026-10-25", … }` (ключ — путь от корня, значение `YYYY-MM-DD`). Сейчас 68 ключей. **Руками файл не править.**

Что попадает в sitemap (через `import.meta.glob`):
1. `src/pages/*.astro` (верхний уровень);
2. `src/pages/posluhy-ta-produktsiia/*.astro`;
3. `src/pages/vykonani-roboty/index.astro` + все карточки через `getCollection('vykonani-roboty')` (`lastmod` по ключу `src/content/vykonani-roboty/<файл>.md`);
4. все `src/pages/ru/**/*.astro`.

Исключения: имя `admin_509`; динамические роуты (`[…]`); по полному пути `ru/vykonani-roboty` (страница-заглушка, также `Disallow` в `robots.txt`). Дубликаты по URL убираются (остаётся первый). Нет записи в карте → дата сборки (запасной вариант, sitemap не ломается).
Итог сейчас: **66 URL** (68 страниц минус `admin_509` и `ru/vykonani-roboty`). **Новую страницу `.astro` или карточку sitemap подхватывает сам** — править ничего не надо.
`public/robots.txt`: `Allow: /`, `Disallow: /admin_509/`, `Disallow: /ru/vykonani-roboty/`, `Sitemap: https://elektroschit.com.ua/sitemap.xml`.
