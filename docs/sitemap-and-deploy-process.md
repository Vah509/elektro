# Як зараз працює карта сайту (sitemap.xml) + скрипт завантаження

Актуально станом на: 2026-07-31

---

## Коротко, суть

Раніше `sitemap.xml.ts` сам рахував `git log` під час білду на Cloudflare
Pages — для кожної сторінки окремо, прямо в момент генерації XML.

Зараз це прибрано. Дати рахуються один раз — у GitHub Actions, під час
обробки чергового ZIP-архіву — і зберігаються у звичайний JSON-файл
`src/data/lastmod-map.json`. `sitemap.xml.ts` більше не звертається до
git взагалі — він просто читає цей готовий файл.

---

## Що робить скрипт завантаження (process-update.js), крок за кроком

Спрацьовує автоматично, коли в `ai-updates/` з'являється новий `.zip`.

1. **Рахує дату останнього оновлення кожної сторінки сайту** — за
   реальною git-історією репозиторію, ДО того, як архів щось змінить.
   На цьому етапі кожна сторінка отримує дату свого останнього коміту.

2. **Для файлів, які є у щойно завантаженому архіві** — примусово
   ставить дату **сьогодні**, а не те, що показав git log.
   Причина: якщо рахувати дати вже ПІСЛЯ того, як файли з архіву
   потрапили в репозиторій, але ДО коміту — git ще не бачить сьогоднішній
   коміт (його ще не було), тож видав би СТАРУ дату замість сьогоднішньої.

3. **Створює тимчасову копію проекту** ("пісочницю") і розпаковує
   архів поверх неї. Реальний репозиторій на цьому кроці ще не чіпається.

4. **Перевіряє/оптимізує фото** з архіву (стискає, якщо завеликі),
   надсилає перше повідомлення в Telegram: що змінилось, що з фото.

5. **Пробує зібрати сайт** (`npm run build`) усередині пісочниці.

6. **Якщо збірка ОК:**
   - записує вже готову карту дат у файл `src/data/lastmod-map.json`
   - переносить усі файли з пісочниці в реальний репозиторій
   - комітить і пушить усе одним комітом (файли проекту + карта дат +
     видалення оригінального ZIP з `ai-updates/`)
   - надсилає друге повідомлення в Telegram: 🟢 успішно

   **Якщо збірка НЕ ОК:**
   - реальний репозиторій НЕ змінюється взагалі — ні файли, ні дати
   - надсилає друге повідомлення в Telegram: 🔴 помилка збірки, з текстом
     помилки
   - ZIP з `ai-updates/` все одно видаляється і комітиться видалення
     (це відбувається завжди, незалежно від результату збірки)

## Що робить sitemap.xml.ts зараз

Під час білду на Cloudflare Pages:

1. Збирає список усіх сторінок сайту (продукція, портфоліо, `/ru/` тощо)
2. Для кожної сторінки бере дату не з git, а напряму з готового файлу
   `src/data/lastmod-map.json`
3. Якщо для якогось файлу запису в мапі раптом немає — підставляє дату
   білду як запасний варіант, щоб sitemap ніколи не зламався

Переваги такого підходу:
- Cloudflare більше не залежить від git під час білду
- Дати для щойно оновлених сторінок завжди коректні — сьогоднішні,
  а не з попереднього коміту
- Один файл-джерело правди для дат, який видно і можна перевірити
  окремо від самого sitemap
