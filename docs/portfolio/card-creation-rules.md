# Правила создания карточек «Виконані роботи»

Документ для проекта, который создаёт карточки портфолио. Сверено с `src/content/config.ts`, `src/pages/vykonani-roboty/*`, `Work*`-компонентами и 39 существующими карточками, 2026-10-28.
Проект карточек отвечает ТОЛЬКО за: `src/content/vykonani-roboty/<slug>.md` + фото `src/assets/images/vykonani-roboty/<slug>/*.jpg`. Код сайта, страницы и реестр тегов он не меняет (новое значение реестра — отдельный согласованный ZIP).
Общаемся по-русски; весь текст карточки — на украинском.

---

## 1. Где лежат файлы

| Что | Путь | Пример |
|---|---|---|
| Карточка | `src/content/vykonani-roboty/<slug>.md` | `src/content/vykonani-roboty/shafa-dymovydalennia-4kvt-pryamyi-pusk.md` |
| Фото карточки | `src/assets/images/vykonani-roboty/<slug>/<файл>.jpg` | `src/assets/images/vykonani-roboty/shafa-dymovydalennia-4kvt-pryamyi-pusk/shafa-dymovydalennia-4kvt-pryamyi-pusk-zovnishniy-kyiv-2026-10-01.jpg` |
| Пути фото В `.md` | `/images/vykonani-roboty/<slug>/<файл>.jpg` | как будто файл в `public/` — **так и писать** |

- **Фото НЕ кладутся в `public/images/`** (там только `og-default.jpg`).
- **`<slug>` папки = имени `.md` без расширения** = URL `/vykonani-roboty/<slug>/`. Slug: латиница, цифры, дефисы, без пробелов; задаёт тип + ключевой параметр (`hrshch-avr-250a-3-vvody`, `shafa-dymovydalennia-4kvt-pryamyi-pusk`).
- Только `.jpg`/`.jpeg`. Если файл по указанному пути не найден — **сборка падает** (ZIP не попадёт в репозиторий, придёт 🔴).

## 2. Поля карточки (frontmatter)

Схема: `src/content/config.ts` (Zod). Все поля, которых нет в таблице как «обязательные», имеют значения по умолчанию.

| Поле | Тип | Обяз. | Правило |
|---|---|---|---|
| `id` | число | ✅ | `YYMMDDHHMMSS` (12 цифр, напр. `261021071110`); у старых карточек 7 цифр (`YYMMDDN`). Без кавычек, уникальный |
| `title` | строка | ✅ | становится **H1 карточки** и названием в каталоге. На украинском |
| `seoTitle` | строка | рекомендуется (всегда задавать) | `<title>` страницы. **≤ 60 символов, считая « \| elektroschit.com.ua»** (допустимо 61–65, больше — нет). Не задан → подставится `title + " \| elektroschit.com.ua"` (обычно слишком длинный) |
| `date` | дата | ✅ | `YYYY-MM-DD`, без кавычек. По дате сортируется каталог (новые первыми) и разрешаются ничьи в «Схожих работах» |
| `types` | массив | ✅ (мин. 1) | только значения из `src/data/tags-registry.ts → TYPE_LABELS`. Первый type определяет подпись «Інші роботи — …» в блоке схожих |
| `tags` | массив | нет | только из `TAG_LABELS`. Участвуют в фильтрах каталога и в расчёте схожих |
| `properties` | массив | нет | только из `PROPERTY_LABELS`. Выводятся на карточке, в фильтрах пока не участвуют |
| `description` | строка | ✅ | meta description страницы. **150–160 символов** (целевой диапазон) |
| `specs` | массив `{label, value}` | нет | таблица характеристик; пусто → блок не выводится |
| `brands` | массив строк | нет | «пилюли» брендов (`["ETI"]`); пусто → блок не выводится |
| `photos` | массив `{src, caption}` | ✅ (мин. 1) | **первое фото = главное на карточке и обложка в каталоге**. `caption` = alt и подпись в лайтбоксе |

Тело файла (после `---`) — обычный Markdown (абзацы, при необходимости списки). Рендерится как описание. Заголовков H1 в тексте не использовать (H1 строит шаблон из `title`).

Допустимые `types/tags/properties` — `portfolio/tags-registry.md`. Неизвестное значение = ошибка сборки.

## 3. YAML: как не сломать сборку

Одна опечатка в YAML роняет тестовую сборку (🔴), реальный репозиторий при этом не меняется.
1. **Все строки в двойных кавычках** — `title`, `seoTitle`, `description`, `caption`, `label`, `value`, `src`. Особенно обязательно, если есть `:` (двоеточие), `#`, `—` в начале, `[`, `{`, `%`, `@`. Реальный случай поломки: значение с двоеточием без кавычек (`…1,5 кВт: прямий пуск`).
2. Внутренние двойные кавычки в тексте — заменять на «ёлочки» «…» (не `"` внутри `"…"`).
3. Массивы — в одну строку с двойными кавычками: `types: ["dymovydalennia", "dvyhuny"]`; пустой — `tags: []`.
4. `id` и `date` — **без кавычек**.
5. Отступы — пробелами (2), вложенные списки `specs`/`photos` как в примере.
6. Файл в UTF-8.

## 4. Фото карточки

- JPG, длинная сторона ≥ 1200 px желательно (меньше не увеличивается; `process-update.js` сжимает шире 1200 до 1200 px, q85). Сайт сам делает WebP (480/800/1200).
- ≤ **1,9 МБ** на файл (ZIP с телефона ≤ 2 МБ).
- Имя: `<slug>-<дескриптор>-kyiv-YYYY-MM-NN.jpg` (латиница, дефисы, `NN` — 01, 02, …). Пример: `hrshch-avr-250a-3-vvody-zovnishnii-vyhlyad-kyiv-2026-07-01.jpg`.
- Рекомендуемый порядок кадров: 1 — общий вид снаружи (главное), 2 — открытый щит/внутренний монтаж, далее детали (клеммы, маркировка, лицевая панель).
- `caption` — осмысленное описание кадра на украинском (используется как alt-текст: SEO + доступность), не «фото 1».
- В папке не оставлять файлов, не упомянутых в `.md` (сейчас 7 таких: 5 в `shuz-keruvannia-zasuvkoiu`, 2 в `shuz-zasuvka`).

## 6. Как выглядит карточка на сайте (что откуда берётся)

| Элемент | Источник |
|---|---|
| H1, название в каталоге | `title` |
| `<title>` | `seoTitle` |
| meta description | `description` |
| Теги над H1 | `types` + `tags` (подписи из реестра) |
| Бейджи свойств | `properties` |
| Главное фото + миниатюры + лайтбокс | `photos` |
| Блок «Характеристики» (зелёный) | `specs` |
| Блок «Виробники обладнання» (белый) | `brands` |
| «Схожі проєкти» | считается автоматически по `types`/`tags` |
| Hero-фото в каталоге, фильтры, пагинация (15 на страницу) | `photos[0]`, `types`, `tags` |
Фильтры каталога строятся из `types`/`tags`, которые реально встречаются у карточек. В sitemap карточка попадает автоматически; `lastmod` = дата ZIP, в котором её загрузили.
Карточек на русском нет (`/ru/vykonani-roboty/` — заглушка).

## 7. Порядок доставки (кратко; полностью — `docs/site/deploy-and-sitemap.md`)

1. Один ZIP = одна карточка (или несколько маленьких). **ZIP без корневой папки**, внутри `src/content/vykonani-roboty/<slug>.md` и `src/assets/images/vykonani-roboty/<slug>/*.jpg`.
2. **Размер ZIP ≤ 2 МБ** (больше — падает загрузка с телефона). Много фото → несколько ZIP: сначала фото-архивы, `.md` — **последним** (`.md` без фото ломает сборку).
3. Загрузка: GitHub → `ai-updates/` → Upload files. Результат — два сообщения Telegram: 1) список файлов + отчёт по фото («ОК» / «ОПТ»); 2) 🟢 «Оновлення успішне» либо 🔴 с текстом ошибки (тогда ничего не применено).
4. Если нужен НОВЫЙ `type`/`tag`/`property` — сначала согласовать; он добавляется правкой `src/data/tags-registry.ts` отдельным ZIP **до** карточки.
5. Проверка после деплоя: открыть `/vykonani-roboty/<slug>/` и каталог; прогнать `node audit-site.mjs https://elektroschit.com.ua prod` (файл лежит в пакете проекта) — должно быть 0 🔴 и 0 🟡; присылать оба файла `audit-summary-prod.md/.json`.
6. `delete.txt` в ZIP не работает.

## 8. Удаление и замена файлов

Только через `ai-deletes/`: `.txt`, один путь на строку, от корня репозитория, без `/` в начале (`src/assets/images/vykonani-roboty/<slug>/<файл>.jpg`, `src/content/vykonani-roboty/<slug>.md`).
Порядок: 1) пробный `dry-<имя>.txt` → 🟡 «N / 0 / 0»; 2) такой же список без `dry-` → 🟢. Разрешены пути в `public/`, `src/`, `docs/`; лимит 300 строк; любой отклонённый путь отменяет весь список; файл, на который остались ссылки, не удалится (сборка в staging упадёт → 🔴).
Замена фото: залить файл с тем же именем в ZIP или новый файл + правка `src` в `.md`.

## 9. Типичные ошибки сборки

| Симптом (🔴) | Причина | Что делать |
|---|---|---|
| `[photo] Файл не знайдено: /images/vykonani-roboty/…` | опечатка в `src` или фото не в ZIP / не в `src/assets/images/vykonani-roboty/<slug>/` | исправить путь/добавить фото |
| Ошибка схемы (`types` … Invalid enum value) | значение не из реестра | заменить на допустимое или согласовать новое |
| YAML parse error | двоеточие/кавычки в строке | взять строку в двойные кавычки |
| `date` / `id` invalid | дата в другом формате; `id` в кавычках | `2026-10-21`, `261021071110` без кавычек |
| `photos` Required / Array must contain at least 1 | пустой список фото | добавить минимум 1 фото |

## 10. Чек-лист карточки

- [ ] `<slug>` совпадает: имя `.md`, папка фото, пути в `photos`.
- [ ] `id` (12 цифр), `date` — без кавычек; `title`, `seoTitle`, `description` — в кавычках.
- [ ] `seoTitle` ≤ 60 (макс. 65) вместе с « | elektroschit.com.ua»; `description` 150–160.
- [ ] `types` минимум 1, все значения из реестра; `tags`/`properties` — тоже.
- [ ] `photos` ≥ 1, первое — лучшее общее фото, у каждого осмысленный `caption`, имена `…-kyiv-YYYY-MM-NN.jpg`.
- [ ] Фото лежат в `src/assets/images/vykonani-roboty/<slug>/`, JPG, ≤ 1,9 МБ.
- [ ] В папке нет лишних неупомянутых фото; в тексте нет H1.
- [ ] ZIP без корневой папки, ≤ 2 МБ, фото раньше `.md`.
