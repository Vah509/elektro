# Фото: как лежат, как называются, как обрабатываются

Сверено с `src/utils/photo.ts`, `src/components/Photo.astro`, `scripts/lib/optimize-photos.js`, 2026-10-28.
Заменяет старые правила («Pillow, quality 82», «лайтбокс несовместим с `src/assets/`», «фото в `public/images/`») — они устарели.

---

## 1. Главное правило

Все фото сайта (продукты, главная, портфолио) лежат в **`src/assets/images/<папка>/`** как `.jpg`/`.jpeg`.
В коде страниц и в `.md` карточек пути пишутся строкой **`/images/<папка>/<файл>.jpg`** — как будто файл в `public/`. Хелпер `photo.ts` превращает строку в путь `/src/assets/images/…` и находит файл.
`public/images/` содержит **только `og-default.jpg`** (og:image/JSON-LD). Новые фото в `public/images/` не класть.

| Папка | Кто использует |
|---|---|
| `home` | `index.astro`, `ru/index.astro` |
| `hrshch`, `dymovydalennia`, `dvyhuny`, `shuz`, `krm`, `zenitni-lihtari`, `ahro`, `plk` | продуктовые страницы (UA и RU используют одни и те же файлы) |
| `vykonani-roboty/<slug>/` | карточка `src/content/vykonani-roboty/<slug>.md` |

## 2. Как это работает в сборке

1. `photo.ts`: `import.meta.glob('/src/assets/images/**/*.{jpg,jpeg,JPG,JPEG}', {eager:true})` собирает метаданные всех фото.
2. `resolvePhoto('/images/x/y.jpg')` → метаданные `/src/assets/images/x/y.jpg`. **Файла нет — сборка падает** с сообщением `[photo] Файл не знайдено` (так и задумано: ошибка в пути не пройдёт незамеченной; тестовая сборка в staging не пустит такой ZIP в репозиторий).
3. `Photo.astro` рисует `<Image>` с WebP, quality 78, `srcset` из ширин `[480, 800, 1200]` (или заданных `widths`), ширины ограничены реальной шириной оригинала (маленький оригинал не увеличивается), `decoding="async"`, автоматические `width/height`.
4. `fullUrl(path)` — URL наибольшего WebP (до 1200 px) для лайтбокса и подмены главного фото; это тот же файл, что в `srcset` (дубликатов в сборке нет).
5. Итоговые файлы: `/_astro/<имя>.<хеш>.webp`. Старые URL `/images/...jpg` больше не существуют (временная потеря индексации старых адресов в Google Картинках — известное следствие).
6. `getImage({unoptimized:true})` в Astro 4.15/4.16 не работает — не использовать.

Вес: 480 px ≈ 33 КиБ, 800 px ≈ 72 КиБ, 1200 px ≈ 98 КиБ (средние значения замеров).
Время сборки: ~959 сгенерированных WebP, холодная сборка 68 страниц ≈ 2 минуты (замер 2026-10-28, песочница); повторные быстрее за счёт кэша Astro. Каждый ZIP запускает тестовую сборку в staging, и ещё раз сборку делает Cloudflare.

## 3. Где используется какой `sizes` (для новых мест — копировать)

| Место | `sizes` | widths |
|---|---|---|
| Hero-коллаж продукта (4 шт.) | `(max-width: 900px) 50vw, 240px` | 480/800/1200 |
| Галерея, большое фото | `(max-width: 900px) 100vw, 600px` | 480/800/1200 |
| Галерея, малое фото | `(max-width: 900px) 50vw, 380px` | 480/800/1200 |
| Главное фото карточки | `(max-width: 900px) 100vw, 800px` | 480/800/1200 |
| Миниатюры карточки | `(max-width: 900px) 72px, 200px` | 240/480 |
| Каталог (обложки) | `(max-width: 560px) 100vw, (max-width: 900px) 50vw, 380px` | 480/800 |
| «Схожие работы» | `(max-width: 560px) 100vw, (max-width: 900px) 50vw, 280px` | 480/800 |

Загрузка: LCP-кандидат — `loading="eager"` (+ `fetchpriority="high"` у первого). Первые 2 фото коллажа eager, первое с high; галерея и всё остальное lazy; в каталоге первые 3 карточки eager.

## 4. Требования к файлу

- Формат: **только JPG/JPEG** (другие расширения glob не видит → «файл не знайдено»).
- Длинная сторона ≥ 1200 px желательно (меньше — не увеличивается). `process-update.js` шире 1200 px сжимает до 1200 px, JPEG quality **85** (Node.js + `sharp`); ≤ 1200 px оставляет как есть. Это предварительная обработка архива; WebP q78 делает уже сборка.
- Размер файла ≤ **1,9 МБ** (загрузка ZIP с телефона через GitHub UI падает на 4–6 МБ, безопасно ≤ 2 МБ на ZIP).
- Имя: латиница, цифры, дефисы, без пробелов и кириллицы.

### Имена
| Где | Шаблон | Пример |
|---|---|---|
| Продукт, hero-коллаж | `<тема>-<дескриптор>-kyiv-YYYY-MM-c1…c4.jpg` | `hrshch-vrshch-odynochnyy-shkaf-vvid-kyiv-2026-06-c1.jpg` |
| Продукт, галерея | `<тема>-<дескриптор>-kyiv-YYYY-MM-01…08.jpg` (01 — большое) | `hrshch-avr-250a-zovnishnii-vyhlyad-kyiv-2026-06-01.jpg` |
| Карточка портфолио | `<slug>-<дескриптор>-kyiv-YYYY-MM-NN.jpg` | `shafa-dymovydalennia-4kvt-pryamyi-pusk-zovnishniy-kyiv-2026-10-01.jpg` |

Комплект продукта = 12 файлов: 4 коллаж + 8 галерея. Страница ссылается на них строками `/images/<папка>/<файл>.jpg`.
Карточка: папка `<slug>` = имени `.md` без расширения; первое фото в `photos:` = главное фото и обложка в каталоге; минимум 1 фото.

## 5. Лайтбокс и фото

- Продукты: `em-site.js` читает `data-full` (галерея — на `.em-gallery-item`, коллаж — на `<img>`, потому что `Photo` вызван с `full`) → WebP 1200.
- Карточки: `WorkPhotos` передаёт массив `{src, caption}` с `fullUrl()` в `window.emOpenWorkLightbox`.
- При смене главного фото кликом по миниатюре скрипт сначала делает `removeAttribute('srcset')` — иначе браузер игнорирует новый `src`.

## 6. Как добавить / заменить / удалить фото

| Задача | Как |
|---|---|
| Добавить фото продукта/главной | ZIP: `src/assets/images/<папка>/<файл>.jpg` + код страницы со ссылкой на `/images/<папка>/<файл>.jpg`. Фото-ZIP можно грузить раньше кода (пока не используются — не мешают); **код-ZIP раньше фото грузить нельзя** — сборка упадёт |
| Добавить карточку | ZIP: фото в `src/assets/images/vykonani-roboty/<slug>/` + `src/content/vykonani-roboty/<slug>.md` (одним архивом или фото раньше `.md`) |
| Заменить фото | залить файл с тем же именем (перезапишется) или с новым именем + правка ссылки |
| Удалить фото | только через `ai-deletes/` (пути `src/assets/images/...`), см. `deploy-and-sitemap.md`. Перед удалением убедиться, что на файл нет ссылок (иначе сборка в staging упадёт — удаление отменится) |
| Фото > 2 МБ ZIP | несколько ZIP по одной папке/небольшими пачками; код-ZIP последним |
